# "다시, 말해" (say-it-again) — 프로젝트 계획

> 역할·스택은 화면 설계(`docs/wireframe.webp`) 기준으로 조정됨. 데이터 형태의 최신 기준은 `docs/api.md`.

## 1. 행사 개요 및 규칙
- 행사: 2026 제1회 컴퓨터공학과 해커톤 L/NKerthon (건국대 글로컬캠퍼스)
- 개발 가능 시간: 10/1(목) 19:30 ~ 10/2(금) 11:30 (16시간). 기능 코드 커밋은 19:30 이후.
- 발표: 10/2(금) 13:30~14:30, 팀당 발표+시연+질의응답 총 6분 내외 (실제 시연 3~4분)
- 발표자료(PDF/PPT) 필수 구성: ① 문제 정의 및 주제 연관성 ② 아이디어 및 해결 방안 ③ 주요 기능 및 구현 방법 ④ 결과물 및 시연 ⑤ 기대 효과 및 활용 방안
- 심사(100점): 주제 적합성/문제 정의 20, 창의성/차별성 20, 기술 구현/완성도 30, 실용성/발전 가능성 20, 발표/질의응답 10. 동점 시 기술 구현 → 창의성.
- 주제: "우리가 바꾸는 캠퍼스의 하루"
- 규칙: 생성형 AI·코딩 도구 허용. 외부 API/오픈소스는 발표에서 명시. 표절·대리 개발 금지. 시연 영상/캡처 백업 권장.

## 2. 프로젝트 정의
- 한 줄 소개: 대학생의 말하기 연습을 AI가 진단. 어디서 버벅였는지, 왜 막혔는지, 어떻게 다시 말하면 좋은지까지 알려준다.
- 문제: 강의 발표, 어학 스피킹, 면접을 혼자 연습할 때 피드백해줄 사람이 없다. 기존 앱(Orai, Speeko, Speak AI, SayNow AI 등)은 필러워드 횟수 같은 수치에서 끝난다.
- 차별점: 침묵·정체 구간(패닉존)을 타임스탬프로 잡고, LLM이 그 구간의 문맥을 보고 "왜 막혔는지" 진단하며 대안 대본까지 제시. 대본 위에 문제 지점을 직접 하이라이트.
- 포지셔닝: 문제정의는 "대학생활의 말하기 3대 순간(강의 발표 / 어학 스피킹 / 면접)". 시연은 "강의 발표" 모드 하나로 고정, 나머지 두 모드는 확장성으로 설명.

## 3. 입력 모드
mode: presentation | speaking (요청·응답 상세는 `docs/api.md`)
- 발표(`presentation`): language는 `ko` 고정. `level`은 assignment(과제 발표) | exam(시험 발표) | keynote(큰 강연). 5분 단위 녹음 파일을 최대 5개 보낸다. `level`은 LLM 프롬프트에 함께 전달한다. 발표 자료(PDF)는 화면에 보여 주는 용도이며 서버로 보내지 않는다.
- 어학 스피킹(`speaking`): language는 `en` 고정. `exam`은 TOEIC-Speaking | opic. 질문별 답변 녹음을 최대 5개 보내고, 질문 문자열은 프론트가 가지고 있다가 `questions`로 함께 보낸다.
- 모드별로 필러워드 사전, LLM 평가 기준을 바꾼다.
  - 필러워드: 확실한 군말(ko: 어/음/아, en: um/uh/er)은 항상, 애매한 말(ko: 그/저/이제/막/그러니까, en: like/so/well/actually)은 앞뒤 간격이 길 때만 필러로 본다.
  - 발표: 구어체 적합성, 문장 길이, 구조 (`level`별 기준은 프롬프트로 전달)
  - 스피킹: 질문 적합성, 문법·어휘 정확성 (문법 항목은 스피킹에서만)

## 4. 핵심 플로우
녹음 파일 1~5개 → 파일마다 병렬 STT(단어 타임스탬프) → 파트별로 서버가 줄 단위 분할 + 패닉존 삽입 → 필러워드/중복 단어 탐지(코드) → 파트별 LLM 병렬 호출(번호 붙은 스크립트)로 원인 진단 + 표현 개선 + 최종 대본 → 총평 LLM 1회 호출(파트별 요약만 입력) → 합산(`charts`, `analysis`) → 스크립트 하이라이트 → 총평 화면

녹음 파일 하나가 응답의 `parts` 하나가 된다 (`docs/api.md`).

## 5. 스크립트 데이터 구조
서버가 단어 사이 간격(gap)을 계산해 직접 만든다.

### 5-1. 분할 규칙
| 단어 사이 간격 | 처리 |
|---|---|
| 0.8초 미만 | 같은 줄 |
| 0.8초 이상 ~ 2초 미만 | 줄바꿈 |
| 2초 이상 | 줄바꿈 + pause 줄 삽입 (패닉존) |
- 문장부호(. ? !) 뒤, 한 줄 12단어 초과 시에도 줄바꿈. 녹음 맨 앞·뒤 침묵은 무시.
- 상수 LINE_GAP=0.8, PANIC_GAP=2.0, MAX_WORDS=12 — 실제 샘플로 튜닝.

### 5-2. 데이터 형태
`docs/api.md`의 `Line[]`(`{start, end, words, pause?}`)을 기준으로 한다. 하이라이트는 파트 안의 전체 단어 번호 범위(`from`~`to`)로 표시하므로 줄을 넘는 문장·구·절도 표시할 수 있다.

### 5-3. 렌더링 · LLM 입력
- pause 줄은 "⏸ N.N초 정지" 마커. 바로 앞 줄 끝부분을 패닉존 하이라이트. 마커 클릭 시 원인과 대안 대본 표시.
- LLM에는 번호 붙은 입력을 준다:
  ```
  [0] 0:동해물과 1:백두산이 2:마르고 3:닳도록
  [1] (침묵 3.2초)
  [2] 0:하느님이 1:보우하사 ...
  ```
  응답 후 범위를 벗어난 인덱스는 폐기.

## 6. 화면 구성
### 6-1. 스크립트 하이라이트 (5색, 색 + 밑줄 모양 병용)
| 색 | 의미 | 대상 | 스타일 |
|---|---|---|---|
| 빨강/주황 | 막힌 지점 | 패닉존 직전 구간 | 진한 배경 + 굵은 실선 |
| 노랑 | 군더더기 | 필러워드(낱개 얇은 밑줄), 필러 몰린 문장(연한 배경) | |
| 보라 | 반복 | 중복 단어 | 물결 밑줄 |
| 파랑 | 표현 개선 | 모호·약한 표현, 문어체, 부정확한 어휘 | 점선 밑줄 |
| 초록 | 문법 | 문법 오류 (스피킹 모드만) | 이중 밑줄 |
- 세부 유형은 툴팁 라벨과 상단 칩 필터로 구분.
- 겹칠 때 배경색은 최상위 1개(빨강>노랑>보라>파랑>초록), 나머지는 밑줄 + 툴팁 "이슈 N개".
- 기본은 빨강+노랑만 켬, 나머지는 칩으로. 프로젝터 대비 밑줄 모양·두께로도 구분.
- 표현 개선은 영향도 순 최대 8개. 패닉존은 긴 상위 3~5개 강하게, 나머지 옅게.
- 중복 단어: 공백 분리 후 끝 조사 정규식 제거, 5문장 윈도우에서 같은 어간 3회 이상이면 플래그.

### 6-2. 총평 화면 (5개 구성)
데이터는 `docs/api.md`의 `charts`, `analysis`, `parts[].final`.
1. 카테고리 비율 차트: 막힌 지점·군더더기·반복·표현 개선·문법·정상 단어 6개 (`charts.categoryRatio`)
2. 중복 단어 차트, 보라색 (`charts.repeatTop`)
3. 필러워드 차트, 노란색 (`charts.fillerTop`)
4. 분석 총평 (`analysis`): 점수(정상 단어 비율), 핵심 지표(WPM, 필러 수, 패닉존 횟수·총 정지 시간 등), 한 줄 총평, 가장 먼저 고칠 3가지, 전체 코멘트(`summary.comment`)
5. 최종 대본: 파트별 수정 대본 (`parts[].final`, 토익 Part 1은 없음)

## 7. 기술 스택
- frontend: React(Vite) + TypeScript + TailwindCSS + DaisyUI, MediaRecorder(webm), recharts. 모바일 우선 반응형.
- backend: Node.js + Express + TypeScript, multer, cors, dotenv
- STT: `openai` 패키지, whisper-1, timestamp_granularities ["word","segment"], response_format verbose_json. webm 그대로 전송. 한국어 침묵 검출 초반 실측.
- LLM: OpenAI API (`openai` 패키지), Structured Outputs(JSON schema)로 구조화 JSON. 모델명은 서버 설정 상수로 관리
- 저장: DB 없음. 로컬 실행, 모바일 필요 시 ngrok.

## 8. LLM 응답 스키마
녹음 파일(파트)마다 병렬로 한 번, 전체 총평은 파트별 요약만 받아 한 번 더 호출한다.

파트별 호출 (입력: 번호 붙은 스크립트 + 모드·`level`·`exam`·질문 문자열):
```json
{
  "highlight": [
    { "line": 2, "from": 3, "to": 6, "category": "panic|expression|grammar", "reason": "...", "fixed": "..." }
  ],
  "final": ["수정된 문장", "..."],
  "comment": "..."
}
```
- `line`, `from`, `to`는 입력의 줄 번호와 줄 안 단어 번호이고, 서버가 응답 `highlight`의 파트 전체 단어 번호로 바꾼다. 범위를 벗어나면 폐기한다.
- `comment`는 스피킹에서만 받는다. 토익 Part 1(지문 읽기)은 `final`을 빈 배열로 돌려준다.

총평 호출:
```json
{ "headline": "...", "topPriorities": ["...","...","..."], "comment": "..." }
```
- 필러·중복은 코드가 찾으므로 LLM에 요청하지 않는다. 표현 개선은 파트당 최대 8개로 명시한다.
